# 沙箱与安全

## 后端自动探测

`agent-sandbox` 按平台探测可用后端，分三个层级：

| 层级 | 含义                                       |
| ---- | ------------------------------------------ |
| L1   | 进程内 WASM 隔离（插件工具）               |
| L2   | 原生进程沙箱（默认工作层）                 |
| L3   | 微型虚拟机（Firecracker/QEMU，仅特殊负载） |

L2 的具体实现按平台选择：

| 平台    | 后端           | 能力                                             |
| ------- | -------------- | ------------------------------------------------ |
| Linux   | `bwrap`        | 完整 mount 命名空间隔离（推荐）                  |
| Linux   | `landlock`     | 文件系统圈定 + seccomp 拒绝列表；无法限制网络    |
| macOS   | `sandbox-exec` | Seatbelt 配置                                    |
| Windows | `job`          | Job Object：资源限制 + 进程树终止；文件/网络开放 |
| 任意    | `none`         | 兜底：不隔离，但会明确提示                       |

装了 `bubblewrap` 就自动用它；没有则退到 `landlock`，再没有则 `none`。

## 每条命令都经过的限制

`bash` 与测试运行器都走 `SandboxBackend::run_command`，这一层统一做四件事：

- **环境变量白名单**——`*_KEY`、`*_TOKEN`、`*_SECRET` 一律拦截，密钥不会随环境泄进子进程
- **资源上限**——内存与进程数可配，超时后清理整个进程树，不留孤儿
- **命令审计**——解析成 shell AST 后分级
- **出网控制**——`auto`（逐命令审计）/ `allow` / `deny`，另有常驻白名单与黑名单

## 审计分级

| 等级     | 例子                     |
| -------- | ------------------------ |
| 关键     | `rm -rf`、覆盖写关键路径 |
| 提权     | `sudo` 及其他提权手段    |
| 网络变更 | 出网的写操作             |
| 越界     | 路径落在工作区之外       |

命中即强制确认，风险等级直接标在审批卡片上。

## 权限模式的配合

沙箱负责"即使命令跑起来也伤不到系统"，权限门负责"这条命令该不该跑"。两者独立：

- `default` / `acceptEdits`：进程类调用逐条确认
- `auto` / `bypassPermissions`：不逐条确认，但仍在沙箱里执行
- `dontAsk`：直接拒绝需要确认的调用

想彻底关掉沙箱（例如调试驱动问题），可在设置里关闭沙箱总开关，此时进程工具走 `none` 后端并给出明确提示。

## 桌面控制的例外

`screenshot` / `computer` 刻意不走沙箱——它们需要访问显示服务器。`bwrap` 的 `--clearenv` 与 `--tmpfs /tmp` 会让 X socket 不可达，工具在沙箱里根本无法工作。因此这一块完全靠权限门把关：`computer` 属控制类，默认必须经人工批准。
