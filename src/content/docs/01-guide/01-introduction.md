# 介绍

Husk 是一个运行在本机的编码 Agent。它能读代码、改代码、跑测试、查资料；写操作需要你确认，命令在沙箱里执行。推理与编排都在一个与界面无关的 Rust 内核里，桌面应用和命令行是接在这同一个内核上的两个前端。

## 定位

网页聊天框适合问答，编程却是持续、多分支、需要审查的工作。Husk 做成本地应用，是因为：

- **并行会话**——每个会话跑在独立的内核线程上，后台轮次不阻塞前台操作，多个项目可以同时推进
- **本地工具**——文件读写、shell、git、测试运行器都发生在你的工作目录，并经过权限裁决与沙箱
- **可审查**——思考、工具调用、审批卡片、变更 diff 都在流里，随时展开回看
- **成本可见**——上下文占用、缓存命中、累计花费实时显示在标题栏

## 形态

Husk 有两种形态，共享同一套内核、配置与会话存储：

| 形态     | 入口                         | 场景                                 |
| -------- | ---------------------------- | ------------------------------------ |
| 桌面应用 | `crates/app-tauri`（husk）   | 日常编程协作，完整界面               |
| 命令行   | `crates/app-cli`（husk-cli） | 脚本、CI、一次性任务（`--headless`） |

另有终端界面 `crates/app-tui`（husk-tui），功能与桌面端对齐的子集。

## 三种模式

Husk 的代理有三种模式，共用同一套工具注册表，区别在于可用工具与回合何时结束：

| 模式         | 可用工具                                      | 回合何时结束             |
| ------------ | --------------------------------------------- | ------------------------ |
| 构建 `build` | 完整工具集，可读写、可执行                    | 模型不再调用工具         |
| 计划 `plan`  | 只读工具加 `submit_plan`                      | 同上，并产出结构化方案卡 |
| 目标 `goal`  | 完整工具集加 `goal_complete` / `goal_blocked` | 模型声明目标达成或受阻   |

详见[模式](/docs/features/modes)。
