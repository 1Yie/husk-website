# 权限与审批

## 权限门

每个工具派发前都会经过 `PermissionGate`。它按当前权限模式决定：直接放行、弹审批卡片，还是拒绝。规则优先级固定为 **deny > ask > allow**——任何一条拒绝规则命中，其余放行条件都不再生效。

五种模式，从宽到严：

| 模式     | 标识                | 行为                                     |
| -------- | ------------------- | ---------------------------------------- |
| 跳过权限 | `bypassPermissions` | 完全信任，破坏性操作也不再拦截           |
| 自动     | `auto`              | 绝大多数工具自动通过，仅高风险操作询问   |
| 接受编辑 | `acceptEdits`       | 文件编辑自动通过，进程类工具仍需确认     |
| 默认     | `default`           | 只读工具直接执行；写文件、跑命令逐条询问 |
| 不询问   | `dontAsk`           | 不弹问询，直接拒绝需要确认的操作         |

`default` 是全新安装的起点。模式可以随时切换，立即对下一次工具派发生效，不需要重开会话。

## 工具是怎么被判定的

每个工具注册时都带三样东西：`readonly` 标记、`ToolClass` 分类、`network` 标记。`ToolClass` 决定它在各模式下的待遇：

| 分类       | 例子                                   | 说明                           |
| ---------- | -------------------------------------- | ------------------------------ |
| 观察       | `smart_read`、`smart_grep`、`list_dir` | 只读，各模式基本放行           |
| 会话变更   | `todo`                                 | 只影响本会话状态               |
| 工作区变更 | `fuzzy_patch`、`apply_patch`           | 改动文件，`acceptEdits` 起放行 |
| 进程       | `bash`、`smart_test_runner`            | 执行外部命令，默认必须确认     |
| 控制       | `computer`                             | 操作桌面，默认必须确认         |
| 人机交互   | `ask_question`                         | 向用户提问                     |
| 编排       | `delegate`、`batch_execute`            | 派生或批量执行                 |

## 审批卡片

需要确认的调用会在流里变成一张卡片：工具名、参数摘要、风险等级。命令在展示前会先被解析成 shell AST 并审计分类：

| 等级     | 含义                    |
| -------- | ----------------------- |
| 关键     | 破坏性操作，如 `rm -rf` |
| 提权     | `sudo` 之类             |
| 网络变更 | 出网写操作              |
| 越界     | 路径落在工作区之外      |

命中这些等级时，卡片会明确标出，方便你在批准前看清要执行什么。

## 桌面工具的例外

`screenshot` 只读，按观察类处理。`computer` 属于控制类，各模式下的行为是明确的：

| 模式                         | `computer`                    |
| ---------------------------- | ----------------------------- |
| `default` / `acceptEdits`    | 每次动作都要确认              |
| `dontAsk`                    | 直接拒绝                      |
| `auto` / `bypassPermissions` | 自动放行                      |
| 计划模式                     | 不可用（只保留 `screenshot`） |

## 子代理

子代理拥有和主会话相同的工具注册表，但去掉了几样：`delegate`（不能再套娃）、`ask_question`（无人可问，必须自主推进）、`computer`（不操作你的桌面）。只读子任务可以并行跑。
