# 权限与审批

## 权限门

每个工具派发前都会经过 `PermissionGate`。它按当前权限模式决定：直接放行、弹审批卡片、还是拒绝。

| 模式     | 行为                                     |
| -------- | ---------------------------------------- |
| 默认     | 只读工具直接执行；写文件、跑命令逐条询问 |
| 接受编辑 | 文件编辑自动通过，进程类工具仍需确认     |
| 自动     | 绝大多数工具自动通过，仅高风险操作询问   |
| 不询问   | 全部放行（保留审计与高风险提示）         |
| 跳过权限 | 完全信任，破坏性操作也不再拦截           |

工具的 `readonly` 标记与 `ToolClass`（观察 / 会话变更 / 工作区变更 / 进程 / 控制 / 人机交互 / 编排）共同决定它在各模式下的放行条件。

## 审批卡片

审批请求以卡片形式出现在流中：工具名、参数摘要、风险等级。命令先经审计分类——如检测到 `git push --force`、`rm -rf`、出网写操作或越界路径，卡片会标出对应的风险等级，方便你在批准前一眼看清要执行什么。

## 人机交互工具

`ask_question` 这类 `HumanInteraction` 工具允许 agent 在不确定时结构化地问你（单选/多选/自定义输入）。它不会出现在无头子代理里——子代理必须自主推进。
