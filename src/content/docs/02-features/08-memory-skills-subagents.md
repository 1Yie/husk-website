# 记忆、技能与子代理

## 记忆

记忆让 Husk 跨会话记住关于你的项目的事实，而不必每次重新解释。

- **写入**：模型通过 `remember` 工具主动记录，你也可以用 `/remember <内容>` 直接写入
- **删除**：`/forget` 删除一条记忆
- **存储**：`~/.local/share/husk/memory.db`，按工作区分区，不同项目互不混淆
- **使用**：与当前工作区相关的记忆会被注入系统提示，模型在需要时自己引用

两个开关在「设置 → 通用」：

| 开关     | 作用                                           |
| -------- | ---------------------------------------------- |
| 记忆开关 | 关闭后完全不注入、不写入                       |
| 模型蒸馏 | 关闭后只保留确定性写入，不额外调用模型整理记忆 |

## 技能

技能是一份 `SKILL.md`，内含针对某类任务的专门指令、检查清单与参考脚本。模型按需加载，不占用常驻上下文。

存放位置（按优先级）：

| 路径                       | 说明                    |
| -------------------------- | ----------------------- |
| `<工作区>/.agents/skills/` | 项目级                  |
| `<工作区>/.claude/skills/` | 兼容 Claude Code 的目录 |
| `<工作区>/.pi/skills/`     | 兼容 Pi 的目录          |
| `~/.agents/skills/`        | 用户级，所有项目可用    |

调用方式有两种，效果相同：

- `/技能名` —— 以命令形式触发
- `$技能名 参数` —— 直接调用并传参

`/skills` 列出当前工作区可用的技能。技能的元信息（名称、描述、可用参数）会常驻系统提示，正文则只在真正调用时加载——这是它能承载大量内容又不与上下文争预算的原因。

## 子代理

`delegate` 派生一个上下文干净的新 Agent 处理有边界的子任务。子代理和主代理共享工作区，但只有它自己的那条对话线索，因此不会被主对话的历史带偏。

### 能力与限制

- 默认可写；传 `readonly: true` 则只读
- 同时派发 2–3 个并行任务时，一律只读——避免并发写冲突
- 预算为 48 轮工具调用或 5 分钟，先到者为准
- 注册表里没有 `delegate`：子代理不能再派生
- 没有 `ask_question`：无人可问，必须自主推进
- 没有 `computer`：不操作你的桌面

### 自定义子代理

写成一份 Markdown，放在下列任一目录：

| 路径                       | 说明             |
| -------------------------- | ---------------- |
| `<工作区>/.husk/agents/`   | 项目级           |
| `~/.config/husk/agents/`   | 用户级           |
| `<工作区>/.agents/agents/` | 兼容通用约定     |
| `<工作区>/.claude/agents/` | 兼容 Claude Code |

内置三个：`review`（代码审查）、`test`（测试补齐与修复）、`ui-design`（界面设计评审）。

### 在流里怎么看

父会话只看到一次 `delegate` 调用与它的结果。子代理内部若想观察过程，可以点开卡片——正文与它自己的工具调用按到达顺序交错显示，正在运行时也会实时更新。
