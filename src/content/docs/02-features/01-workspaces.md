# 工作区与会话

## 工作区

一个工作区就是一个目录（通常是代码仓库）。Husk 以工作区为单位组织一切：

- 每个工作区有独立的会话列表，切换工作区即切换上下文
- 会话历史按工作区分别保存，互不相干
- 记忆、架构蓝图、项目级插件都以工作区为作用域
- 部分偏好（模型、权限、模式）可以按工作区固定，覆盖全局默认

打开桌面端后，侧栏列出最近使用的工作区及其会话。办公模式下的工作区单独列出，与编程工作区分开。

## 会话

会话是连续的对话与工具执行记录。每个会话跑在独立的内核线程上：

- 后台会话继续推进，不阻塞前台操作
- 多个会话可以并行，各自持有自己的模型、权限与模式
- 会话可以重命名、归档、删除，也可以从某一轮分叉出新会话

## 并行与多窗口

后台会话持续运行时，界面只订阅当前打开的会话，切回来即可看到完整过程——历史从磁盘补齐，再叠加实时事件。

需要同时盯着两个工作区时，用独立窗口：

```bash
husk --new-window
```

两个窗口可以打开同一会话；历史按消息追加，较旧的写入会被拒绝，避免覆盖另一窗口的记录。

## 存储位置

| 内容       | 位置                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 配置       | `~/.config/husk/config.toml`                                         |
| 开发者设置 | `~/.config/husk/settings.toml`                                       |
| 会话历史   | 数据目录下按工作区分目录，每个会话一份 JSONL，按消息追加并配独立索引 |
| 记忆库     | `~/.local/share/husk/memory.db`，按工作区分区                        |
| 粘贴的图片 | `<工作区>/.husk/attachments/`                                        |
| 项目级插件 | `<工作区>/.husk/plugins/`、`<工作区>/.husk/mcp/`                     |

会话历史不需要全局数据库锁：只有写同一会话时才短暂加锁，因此桌面端、CLI、TUI 可以同时访问。旧版 `sessions.db` 与 JSONL 记录会在首次启动时从校验过的副本导入，原文件保留。
