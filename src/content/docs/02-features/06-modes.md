# 模式

Husk 有三种代理模式，共用同一套工具注册表，区别在于可用工具和回合何时结束。

| 模式 | 标识    | 可用工具                                      | 回合何时结束           |
| ---- | ------- | --------------------------------------------- | ---------------------- |
| 构建 | `build` | 完整工具集，可读写、可执行                    | 模型不再调用工具       |
| 计划 | `plan`  | 只读工具加 `submit_plan`                      | 同上，并产出方案卡     |
| 目标 | `goal`  | 完整工具集加 `goal_complete` / `goal_blocked` | 模型声明目标达成或受阻 |

切换模式会立即换掉当前会话的工具注册表，并重写系统提示里的模式段落，不需要重开会话。

## 构建模式

默认模式。模型可以读、写、执行，按权限门的规则逐条裁决。

## 计划模式

计划模式下写操作工具被移除，模型只能读和搜索，最后通过 `submit_plan` 交出一份结构化方案。方案在流里渲染成一张卡片，包含：

- 步骤，以及每一步涉及的节点（若工作区启用了架构蓝图）
- 拟改动的文件
- 验证方式
- 风险

审阅满意后切回构建模式执行。这样"想清楚再动手"变成了一道明确的关卡，而不是靠提示词约束。

## 目标模式

目标模式给模型一份完成契约：它必须显式调用 `goal_complete` 声明达成，或 `goal_blocked` 声明受阻，回合才结束。适合这类任务：

- 修到测试全绿
- 重构到所有调用点编译通过
- 迁移到某个依赖不再被引用

协议约束还能避免模型在"看起来差不多了"的时候提前收工，也避免它陷入无限自我修正。

`goal_blocked` 会记录受阻原因，并进入等待：需要你补充信息或做决定才能继续。

## 办公模式

除了三种代理模式，桌面端还有办公模式：切换到办公工作区后，工具集偏向文档产出（`office_*` 系列），右侧面板展示产物而不是代码 diff。它和编程工作区各自独立，互不影响。
